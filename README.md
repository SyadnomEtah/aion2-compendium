# AION 2 Beginner Compendium

A sourced beginner guide for the AION 2 global launch (advance access 2026-09-30, launch 2026-10-05). Built as a React 19 single-page app with TypeScript, deployed to GitHub Pages via GitHub Actions. English and Polish, no backend. All user state lives in localStorage.

Live site: https://syadnometah.github.io/aion2-compendium/

## What is inside

- Start Here, Priorities, What to avoid: what to do in the first hours and days, and the mistakes community write-ups warn about.
- Systems, Dungeons and Energy, Premium and Spending: every progression system, the dungeon table, where to spend Odyle Energy and money.
- Eight class guides (Templar, Gladiator, Assassin, Ranger, Sorcerer, Spiritmaster, Cleric, Chanter) with skill priority, a leveling build, stigma picks, Daevanion route, gear, rotation and common mistakes. A Compact view hides the prose and keeps the lists and tables.
- Progression roadmap: 7 phases and 53 checkable milestones with progress bars and a character profile.
- Daily and weekly tracker: tasks as rows, your characters as columns, counters with automatic resets, custom tasks.
- Sources and Glossary: every fact carries an inline source chip with a confidence badge. Most data is from the Korean and Taiwanese release, so anything badged KR-era should be re-verified after the global launch.

Progress, tracker state and the language choice live in the browser's localStorage. The roadmap page has Export and Import buttons for a JSON backup, and a banner reminds you when the last export is older than a week.

## Tech stack

- **Framework**: Vite, React 19, TypeScript, lucide-react icons
- **Routing**: react-router with HashRouter
- **Testing**: Vitest with jsdom
- **Content pipeline**: Python 3.10+ (standard library only) to compile HTML fragments and i18n translations into JSON
- **Deployment**: GitHub Actions (Node 24) to build and deploy `dist/` to GitHub Pages

## Repository layout

```
content/
  fragments/            HTML fragments (one per guide page or page part)
  fragments/tasks.json  tracker task list
  i18n/pl/*.json        Polish block translations keyed by block hash
  i18n/pl.strings.json  Polish UI strings keyed by English text
  i18n/en.blocks.json   English extraction (regenerated by content script)
  specs/                writing contracts (fragment markup, readability, leveling cards, translation rules)

scripts/
  build_content.py      fragments + i18n -> public/content/** and src/generated/**
  *.py                  validators (i18n_check, check, final_check)

public/
  content/tasks.json                      copied from content/fragments/tasks.json
  content/{en,pl}/<pageId>.json           one PageData per page and language
  content/{en,pl}/search.json             search index
  robots.txt, favicon.svg

src/
  generated/meta.json                     counts for sidebar badges and home stats
  generated/ui.pl.json                    Polish UI dictionary (English text -> Polish)
  content-types.ts                        shared TypeScript types for content JSON
  lib/                                    store, i18n, content fetching, static data, time math
  components/                             shell (Layout, Sidebar, TopBar, SearchDialog, LanguagePicker, ThemeToggle) and guide rendering (GuideBody, Card, Toc, ...)
  pages/                                  page components: Home, ClassesPage, RoadmapPage, TrackerPage
  styles/                                 tokens, base, shell, content and pages stylesheets
  App.tsx, main.tsx

.github/workflows/deploy.yml              build and deploy to GitHub Pages on push to main
```

Generated files (`public/content/**`, `src/generated/**`) are committed to the repository so CI needs Node.js only. Regenerate them with `npm run content` after touching `content/`.

## Getting started

Requires Node.js 22.12 or newer (24 LTS recommended, matching CI). Install dependencies:
```bash
npm install
```

Generate content JSON from fragments:
```bash
npm run content
```

Run the dev server (port 5173 by default):
```bash
npm run dev
```

Run tests:
```bash
npm test
```

Run tests in watch mode:
```bash
npm run test:watch
```

Check TypeScript:
```bash
npm run typecheck
```

Build for production:
```bash
npm run build
```

Preview the production build:
```bash
npm run preview
```

## Editing content

Fragments live in `content/fragments/` and follow the contract in `content/specs/FRAGMENT-SPEC.md` (no `<script>`, `<style>`, or inline styles; no em dashes; source chips on every fact).

After editing English text:
```bash
npm run content
```

This runs `python scripts/build_content.py` to assemble fragments, tag them for translation, apply Polish substitutions if available, and write `public/content/` and `src/generated/`.

## Translation workflow

To add Polish translations:

1. Extract English blocks that lack Polish:
```bash
python scripts/build_content.py --extract
```
This writes `content/i18n/todo/en-NN.json` work units for anything still missing.

2. Translate each new unit into `content/i18n/pl/pl-NN.json` following the contract in `content/specs/I18N-RULES.md`. Blocks are keyed by a hash of the English HTML, and the dictionary uses numbered tokens (U+27E6 n U+27E7) as placeholders for atoms like links and icons that the translator must not touch.

3. Validate the translations:
```bash
python scripts/i18n_check.py
```

4. Rebuild:
```bash
npm run content
```

Blocks without a Polish entry fall back to English at runtime, so a partial translation never breaks the page.

## Deployment

The site is deployed to GitHub Pages by GitHub Actions on every push to `main`. The workflow (`.github/workflows/deploy.yml`) runs `npm ci`, `npm test`, `npm run build`, and uploads `dist/` to Pages.

Because the repository is public and the guide is meant to stay unlisted, `index.html` carries `<meta name="robots" content="noindex, nofollow">` and `public/robots.txt` disallows all crawlers. These are the only mechanisms available on GitHub Pages (no custom headers); never remove them.
