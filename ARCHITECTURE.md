# Architecture

Vite + React 19 + TypeScript single-page app, deployed to GitHub Pages by GitHub Actions. Guide content is authored as HTML fragments and compiled by a Python script into JSON that the app fetches at runtime. No backend. All user state lives in `localStorage`.

## Repository layout

```
content/
  fragments/*.html        guide content, one fragment per page or page part (contract: content/specs/FRAGMENT-SPEC.md)
  fragments/tasks.json    tracker task list
  i18n/pl/*.json          Polish block translations keyed by block hash
  i18n/pl.strings.json    Polish UI strings keyed by English text (the single UI dictionary)
  i18n/en.blocks.json     English extraction (regenerated by the content script)
  i18n/en.strings.json    English UI strings found in the app (regenerated by the content script)
  specs/*.md              writing contracts: fragment markup, readability limits, leveling card structure, translation rules
scripts/
  build_content.py        fragments + i18n  ->  public/content/** and src/generated/**
  i18n_check.py           validates Polish block files and UI strings against the English extraction
  check.py, final_check.py   fragment validators (length limits, card order, forbidden markup)
public/
  content/tasks.json                      copied from content/fragments/tasks.json
  content/{en,pl}/<pageId>.json           one PageData per page and language
  content/{en,pl}/search.json             search index
  robots.txt, favicon.svg
src/
  generated/meta.json                     counts for sidebar badges and home stats
  generated/ui.pl.json                    Polish UI dictionary as consumed by the app
  content-types.ts                        shared TypeScript types for everything under public/content and src/generated
  lib/                                    store, i18n, theme, content fetching, static data, time math, progress, tracker, backup, page and TOC contexts
  components/                             shell (Layout, Sidebar, TopBar, SearchDialog, LanguagePicker, ThemeToggle, Toast), guide rendering (GuideBody, BlockRenderer, Card, SourcesCard, Toc, ClassHead, CompareGrid, Tiles), RoadmapSummary, BackupBanner
  pages/                                  Home, GuidePage, ClassesPage, RoadmapPage, TrackerPage
  styles/                                 tokens.css (design tokens, light and dark), base.css, shell.css, content.css, pages.css
  App.tsx, main.tsx
.github/workflows/deploy.yml              npm ci, npm test, npm run build, deploy dist/ to Pages
```

Generated files (`public/content/**`, `src/generated/**`) are committed so CI needs Node only. Regenerate with `npm run content` after touching `content/`.

Routing: `react-router` `HashRouter`. `/` is home, `/:pageId` everything else, unknown id redirects to `/`. A bare `#pageid` hash (old link format without the slash) is rewritten to `#/pageid` at boot and on every `hashchange`. The last visited page is stored (`aion2.page`) and restored when the app opens at `/` with no hash. Every page change scrolls to the top unless a search hit asked for a specific card.

Page titles come from `PAGE_TITLES` in `content-types.ts`, translated through the UI dictionary.

## Content JSON (`public/content/<lang>/<pageId>.json`)

Types live in `src/content-types.ts` and are the contract between the Python script and the React app. Summary:

```ts
interface PageData { id: string; title: string; classId?: string; single: boolean; blocks: Block[] }
type Block = HtmlBlock | ClassHeadBlock | CardBlock | SourcesBlock | PhaseBlock;

HtmlBlock       { type: 'html'; html: string }                  // intro divs, banners, sec-titles, anything else
ClassHeadBlock  { type: 'classHead'; role: string; html: string } // inner HTML of div.class-head (h2, p.lead, div.pills)
CardBlock       { type: 'card'; id; title; titleEn; headExtrasHtml; bodyHtml; bodyAfterHtml?; compare?; tags; level? }
SourcesBlock    { type: 'sourcesCard'; title; bodyHtml; linkCount }  // at most one per page, always the last block
PhaseBlock      { type: 'phase'; id; num; title; goalHtml; milestones: {key; labelHtml; whyHtml}[]; extraHtml }
CompareTable    { heads: string[]; headsEn: string[]; rows: { name; classId?; cellsHtml: string[] }[] }
```

Rules the script applies (so the React side never mutates DOM):

- **Card id**: `<pageId>-c<n>`, n counting non-sources cards from 1 in document order. Existing `id` attributes on `<article>` win. The merged sources card is `<pageId>-sources`.
- **Sources merge**: every `article.card` whose English h3 starts with "Sources" (case-insensitive) and every standalone `div.sources` on the page are merged, in order, into one `SourcesBlock` appended last. Merged parts are separated by `<hr class="srcsep">`. `linkCount` = number of `a.src` inside. Title = translated "Sources used".
- **single**: `true` when the page has exactly one non-sources card. The card then shows no number.
- **Citation chips**: inside `CardBlock.bodyHtml`, `PhaseBlock` html and `headExtrasHtml`, every `a.src` that is not inside `div.sources` or `div.tbl` becomes `<a class="src cite" href=... target="_blank" rel="noopener" data-n="N" title="<original text> (opens in new tab)"><span class="cite-full">original text</span><span class="cite-n">N</span></a>`. N restarts at 1 per card and per phase. Chips inside `div.tbl`, `div.sources` and the sources card keep their original markup.
- **Compare table**: for the `classes` page, the first `div.tbl > table` inside the first card becomes `compare` (`heads` from `thead th` text, `headsEn` the same from the English build, rows from `tbody tr`: `name` = first cell text, `classId` = class whose id the lowercased name starts with, `cellsHtml` = innerHTML of the remaining cells). `bodyHtml` is the body before the table, `bodyAfterHtml` the body after it. The compare text is part of the card's search entry.
- **Phases** (roadmap): `section.phase` -> `PhaseBlock`; `num` = `.phase-num` text, `title` = `h3` text, `goalHtml` = `p.phase-goal` innerHTML, `milestones` from `ul.chk li`: `key` = `input[data-key]`, `labelHtml` = label innerHTML with the `<input>` removed, `whyHtml` = `p.why` innerHTML or empty. Anything else inside `.phase-b` goes to `extraHtml`.
- **Polish**: every translatable block is tagged with a key that is the sha1 of its normalised English HTML (the `Tagger` in `build_content.py`; leaf elements are tagged, mixed containers get their inline runs wrapped in `span`, atoms such as links, icons and inputs become tokens U+27E6 n U+27E7). The Polish HTML is substituted at build time and the tokens are replaced by the original atom markup in order. Blocks without a Polish entry stay English. `titleEn` always holds the English h3 text. Changing the English text of a block changes its key, so that block needs a new Polish entry (`--extract` lists them).
- **HTML hygiene**: output HTML is the fragment markup verbatim apart from the transformations above. No `<script>`, no inline styles. Entities untouched.

Other generated files:

- `public/content/<lang>/search.json`: `SearchEntry[]` = `{ page, pageTitle, cardId, title, text }` for every card and sources card, `text` = lowercased plain text of title + body + compare table + `data-tags`.
- `public/content/tasks.json`: verbatim copy of `content/fragments/tasks.json`.
- `src/generated/meta.json`: `{ cards, sourceLinks, pageCounts: { [pageId]: cards + phases }, compiled: 'YYYY-MM-DD' }` computed from the English build. `cards` counts non-sources cards plus one merged sources card per page that has one.
- `src/generated/ui.pl.json`: `Record<string, string>` built from `content/i18n/pl.strings.json`. React code calls `T('exact English text')`; a miss returns the English.

## React conventions

- Function components, hooks, no class components, no external state library. Contexts: language (`LangProvider`), toast, page actions (expand/collapse all), table of contents (`TocProvider`, lets a page publish its TOC to the layout rail).
- Fragment HTML is rendered with `dangerouslySetInnerHTML` inside components that own the interactive chrome (card header click to collapse, TOC, tiles). Behaviour is derived from the JSON, never from querying or mutating the DOM (scroll-spy and scrolling to an element by id are the only DOM reads).
- `localStorage` keys are stable across releases so returning visitors keep their data. All keys are prefixed `aion2.`: `lang`, `page`, `compact` (citation mode, default true), `classCompact`, `theme`, `nav` (rail collapsed), `toc` (rail hidden), `collapsed` (open/closed state per card id and per roadmap phase id, only ids the visitor changed), `chk`, `profile`, `chars`, `customTasks`, `counts`, `hiddenTasks`, `trk`, `trkReset`, `lastExport`, `bkSnooze`. Access only through `src/lib/store.ts`.
- Backup file format is frozen: `{ version: 2, exported, chk, profile, page, tracker?: { chars, custom, counts, hidden, settings } }`. A file without `tracker` leaves the tracker state untouched on import.
- Languages are listed in `LANGUAGES` in `src/lib/i18n.tsx`; adding one means adding an entry there plus a `public/content/<code>/` folder (the content script must be taught to emit it). The language picker in the top bar is the only switch. Switching refetches content for the new language, no reload. `document.documentElement.lang` follows.
- Theme: `data-theme` on `<html>`, `light` or `dark`, default from `prefers-color-scheme`, toggle in the top bar, applied before first paint from `main.tsx`.
- `body.compact` toggles citation display (CSS shows `.cite-n` in compact mode, `.cite-full` otherwise). Class pages add `.compact` on the page element when `classCompact` is on (hides prose, keeps lists and tables).
- Every English UI string in JSX goes through `T()` (plain text) or `TH()` (inline HTML) from `src/lib/i18n.tsx`. The string is the dictionary key, so it must exist in `content/i18n/pl.strings.json` to be translated; `python scripts/build_content.py --extract` lists the ones that are missing.
- Styling: plain CSS with design tokens in `src/styles/tokens.css` (colour scale, role accents, spacing, radii, shadows, type scale, motion durations, light theme overrides, reduced motion). Class names inside fragment HTML (card, tldr, tip, warn, note, badge, src, cite, tbl, prio, timeline, cols, verdict, pills, chk, why, phase) are styled in `content.css`; do not rename them.
- Layout: CSS grid with a collapsible left navigation rail, a content column (max 1440 px) and, from 1280 px, a right "On this page" rail that can be hidden. Below 1280 px the TOC is a collapsible dropdown at the top of the page. Every guide page ends with a previous/next pager over `PAGE_IDS`.
- Tests: Vitest with jsdom. Pure logic (`lib/time.ts`, `lib/progress.ts`, `lib/backup.ts`, `lib/tracker.ts`) has unit tests; the shell has smoke tests (`App.test.tsx`, `Layout.test.tsx`, `TopBar.test.tsx`).
- Writing style in code comments, README and commit messages: plain prose, no em dashes.

## Data flow

```
content/fragments + content/i18n  --scripts/build_content.py-->  public/content/**, src/generated/**
App load: read lang -> fetch content/<lang>/<page>.json (cached per lang+page) -> render blocks
Search: Ctrl+K or "/" opens the dialog; first open fetches content/<lang>/search.json, filters client side (title matches first, max 40), a hit navigates with the card id in router state and the page expands and flashes that card
Roadmap: phases from content/<lang>/roadmap.json + chk store -> per-phase and overall progress (Home shows the same numbers)
Tracker: content/tasks.json + custom tasks + counts + settings -> table; ticking resets daily/weekly by the stored reset times
```

## Build and deploy

- `npm run content` runs `python scripts/build_content.py` (Python 3.10+, standard library).
- `npm run dev`, `npm test`, `npm run typecheck`, `npm run build` (tsc + vite, `base: '/aion2-compendium/'`), `npm run preview`.
- Search engines: the site is meant to stay unlisted. `index.html` carries `<meta name="robots" content="noindex, nofollow">` and `public/robots.txt` disallows everything. GitHub Pages cannot send custom headers, so these two are the whole mechanism; do not remove them.
- `.github/workflows/deploy.yml`: on push to `main`, Node 22, `npm ci`, `npm test`, `npm run build`, upload `dist/`, `actions/deploy-pages`. Pages source is GitHub Actions.
